# 02 アプリの追加

新しい回答アプリを追加する手順。各層の役割と、なぜそう分けているかは [01 構成](01_構成.md) を参照。

`apps/normal_chat/` が最小の実装例なので、コピーして名前を置き換えるところから始めるとよい。以下、新しいアプリ名を `<app_name>` とする。

## 作るファイル

```
apps/<app_name>/
├── __init__.py
├── <app_name>_controller.py
├── flows/
│   ├── __init__.py
│   ├── flow_data.py
│   └── <app_name>_flow.py
├── nodes/
│   ├── __init__.py
│   └── <node_name>.py
└── prompt_templates.yaml
interfaces/handlers/<app_name>/
├── __init__.py
└── <app_name>_websocket.py
```

変更するファイル:

- `interfaces/urls.py`: エンドポイントの登録
- `Makefile`・`scripts/`: 動作確認用のコマンド(任意)
- `api/README.md`: 動作確認用のコマンドを追加したら、「よく使うコマンド」に足す

## 手順

### 1. prompt_templates.yaml

flow → node → agent の階層で書く。agent には `model_name`・`system_message`・`label` を持たせる(ノードが `LLMAgent` に渡す)。

```yaml
<app_name>_flow:
  <node_name>:
    <agent_name>:
      model_name: ...
      system_message: "..."
      label: "..."
```

- 一番上のキー(`flow_name`)は、全アプリで重ならないようにする。全アプリの YAML は 1 つの store にまとめて読み込まれ、重なると起動時に `set_store` がエラーになる
- `label` は回答の `agent` としてクライアントに送られる

### 2. flows/flow_data.py

ノード間で受け渡すデータを `FlowData` に定義する。`prompt`(入力)と `content`(最終的な回答)は controller が使うので必ず持たせる。

### 3. nodes/

1 ステップごとに 1 クラスを作る。`normal_chat/nodes/normal_node.py` と同じく、次のようにする。

- `__init__` で `ws`・`chat_session`・`flow_data`・agent のテンプレートを受け取る
- 会話履歴が必要なら、ノードが `get_history(chat_session)` で取得して `history=` で agent に渡す
- 回答は `ContentStreamSender` で送り、`try/finally` で `flow_data.content` に移す(途中で切断されても保存できるように)
- DB への保存はしない(flow が行う)

### 4. flows/<app_name>_flow.py

`normal_chat/flows/normal_chat_flow.py` と同じく、次のようにする。

- モジュールの先頭で `set_store(Path(__file__).parents[1] / "prompt_templates.yaml")` を呼ぶ
- `__init__` で `get_prompt_template(FLOW_NAME, <node_name>, <agent_name>)` を取得し、グラフを組み立てる
- ノードはグラフの各ステップの中で生成する
- `arun(prompt)` で `FlowData` を作ってグラフを実行し、`finally` で保存する(保存する内容は `FlowData` から repository の引数に置き換える)

### 5. <app_name>_controller.py

`run_<app_name>(ws, chat_session, text) -> str` を公開する。中身は `normal_chat_controller.py` と同じ形にする(flow の実行 → 後処理の登録 → `send_done`)。

### 6. interfaces/handlers/<app_name>/<app_name>_websocket.py

`interfaces/handlers/normal_chat/normal_chat_websocket.py` をコピーし、次を置き換える。

- 関数名(`<app_name>_websocket`)・ログのメッセージ
- 呼び出す controller: `run_<app_name>`

> 接続の受け付け・タイムアウト・例外時の close はアプリ間で同じ。アプリが増えてきたら `interfaces/handlers/` 直下の共通処理にまとめることを検討する。

### 7. interfaces/urls.py

handler を登録する。`normal_chat_websocket` の登録をコピーし、パスと handler を置き換える。

> `routes/` に分割済み([01 構成](01_構成.md) の「urls.py が長くなったときの分割」)なら、`routes/<app_name>.py` に `<app_name>_router` を作って登録し、`urls.py` で `include_router` する。

```python
from interfaces.handlers.<app_name>.<app_name>_websocket import <app_name>_websocket

api_router.add_api_websocket_route(
    "/ws/<app_name>/{session_uid}",
    <app_name>_websocket,
    dependencies=[Depends(track_connection)],
)
```

### 8. 動作確認(任意)

`scripts/ws_normal_chat.py` をコピーして接続先のパスを変え、`Makefile` にコマンドを足す。

```make
ws-<app_name>:
	uv run scripts/ws_<app_name>.py ${session_uid} "${text}"
```

### 9. 仕上げ

- `make fmt` と `make lint` でエラーがないことを確認する
- 構成を変えた(新しい種類のファイルを足した、など)ときは `docs/` も更新する
